# Product Notes

## 愿景

把 Figma 工作流中那些「重复、靠记忆、难标准化」的环节拆成小工具，每个工具都能独立使用，也能组合成团队效率系统。

## 近期优先级

1. 快捷键热区图：解决学习、分享、输出 PNG 的急用需求。
2. 快捷键数据补全：建立一套可持续维护的快捷键数据库。
3. 学习模式：按场景生成练习卡片，例如「快速整理画布」「组件编辑」「原型连线」。
4. 团队模板：把常用工具输出成分享页或图片，方便团队 onboarding。

## Shortcut Heatmap 的核心假设

- 用户不是只想查快捷键，而是想知道「哪些最值得先记」。
- 键盘热区比纯表格更适合做学习和培训图。
- 排序逻辑应该可解释，至少包含频率、影响力、学习难度、场景标签。
- 输出图片是第一阶段的关键能力，后续再考虑 Figma Plugin 或浏览器扩展。

## 交互方案：组合键解释模式

### 背景

如果热区只高亮主键，例如 `K`，用户仍然需要回到列表里读取 `Command + Option + K`，注意力会在图和文字之间反复切换。

### 目标

当用户指向某个具体快捷键时，热区不仅要高亮主键，还要同时高亮对应修饰键，直接解释完整组合键。

### 第一版交互

1. 默认状态保持热区视图，继续展示高频主键分布。
2. 用户悬停列表项时，键盘进入临时高亮模式：
   `Command + Option + K` 会同时高亮 `Command`、`Option`、`K`。
3. 用户点击列表项时，进入锁定模式，适合停留查看和导出图片。
4. 用户点击清除按钮后，恢复默认热区模式。
5. 导出 PNG / SVG 时，如果当前有锁定快捷键，则保留该锁定态。

### 视觉层级

- 主键：使用更强烈的实体色，作为视觉焦点。
- 修饰键：使用描边或次一级高亮，让用户知道它们需要同时按下。
- 无关键：降低透明度，减少噪音。
- 键盘上方增加当前组合键说明条，减少视线往返。

### 价值

- 降低用户理解组合键的注意力成本。
- 提升热区图在教学、分享和 PNG 导出场景中的表达力。
- 为后续“学习模式”打基础，例如只展示单个快捷键的训练卡片。

## 后续可以讨论的产品形态

- 单页工具站：最快上线，适合多个小工具共用导航。
- Figma Plugin：更贴近使用场景，但开发、审核和权限边界更复杂。
- Chrome Extension：适合增强 Figma Web，但维护成本更高。
- CLI/数据包：适合把规范、快捷键、模板做成团队资产。

## 新方向：Property Lab

### 目标

把 Figma 属性面板从“术语列表”变成“参数结果实验台”。

用户不只是阅读定义，而是能直接看到：

- 这个属性控制什么
- 参数值变化后界面如何变化
- 真实工作中什么时候该这样设
- 常见误解是什么

### 为什么值得做

- 很多人会操作 Figma，但看不懂参数变化背后的布局逻辑。
- 真正困难的不是按钮位置，而是属性值的意义和后果。
- 这个工具适合培训、团队 onboarding、设计系统教育和内容传播。

### 推荐 MVP

第一版只做 `Auto Layout`，避免范围过大。

MVP 包含：

1. 属性实验区：用户直接调整参数。
2. 结果预览区：组件实时变化。
3. 解释卡片区：说明当前参数的意义、适用场景、误区。
4. 映射关系区：给出与 CSS/Flex 的近似对应关系。

### 第一批属性

- Direction
- Padding
- Gap
- Alignment
- Hug / Fill / Fixed
- Wrap
- Absolute Position

### 不建议第一版优先做的内容

- 单纯数值型基础属性，例如 X / Y / W / H
- 过于分散的零碎属性百科
- Prototype 全量属性
- Variables 全量系统

### 产品形态建议

最适合的形式是 `面板镜像模式 + 实验台`：

- 左侧接近 Figma 属性面板
- 右侧显示实时预览结果
- 下方输出解释、误区和场景建议

这样用户可以把 Figma 面板里的认知直接迁移过来。

## 新方向：Token Lab

### 目标

把一批已有界面图片整理成可导入 Figma Variables 的 token 初稿。

用户不是缺少界面素材，而是缺少把这些素材系统化沉淀到 Figma 中的生产工具。

### 解决的问题

- 图片里有明显视觉规律，但缺少统一提炼方式
- 提炼出的值很零散，难以归并成可维护 token
- 团队想快速建立变量基础层，但手工录入成本高
- 从旧项目补建设计系统时，缺少高效起稿工具

### 推荐 MVP

第一版聚焦：

1. 上传多张风格一致的界面图
2. 提取颜色、间距、圆角等高价值基础 token
3. 对离散值做聚类与归并
4. 生成 primitive 与 semantic 两层草案
5. 支持人工确认、重命名、合并与删除
6. 直接写入当前 Figma 文件的 local variables

### 为什么值得做

- 很多团队不是没有设计，而是没有被整理成变量资产
- 从截图反推 token，比从零手写变量更符合真实工作流
- “半自动起稿 + 人工确认”比“全自动生成设计系统”更现实
- 这个方向天然适合继续扩展到命名转换、JSON 导入导出和团队同步

### 不建议第一版优先做的内容

- 完整 typography token 体系
- 复杂 effect token
- 多品牌混合图片的自动统一
- 无人工确认的一键全自动变量生成
